Lambda 連線池優化：解決 PostgreSQL "connection already closed" 錯誤

前言

在 AWS Lambda 環境中使用 PostgreSQL 資料庫時，經常會遇到 “connection already closed” 的錯誤。這個問題主要源於 Lambda 的容器重用機制與傳統資料庫連線管理方式的不匹配。本文將詳細說明問題成因，並提供使用 SQLAlchemy 連線池的完整解決方案。

處理問題

問題描述

在 Lambda 函數中使用 psycopg2 直接連線 PostgreSQL 時，會隨機出現連線已關閉的錯誤，即使設定了適當的連線超時時間。

根本原因

  1. Lambda 容器重用：Lambda 會重用容器，但不保證連線持續有效
  2. 網路中斷：Lambda 與 RDS 之間的網路可能因 VPC、NAT Gateway 等因素中斷
  3. 連線檢測不足：connection.closed 只能檢測客戶端主動關閉，無法檢測網路斷線
  4. RDS 端主動關閉：資料庫可能因維護、資源限制等原因主動關閉連線

處理過程

步驟一：分析原有連線管理問題

問題點：

  • 無法檢測到網路中斷導致的連線失效
  • 沒有自動重連機制
  • 缺乏連線健康檢查

關鍵設定說明

設定項目 值 說明 Lambda 重要性
pool_pre_ping True 🔑 每次使用前測試連線 必要 - 解決死連線問題
pool_size 1 每個容器最多 1 條連線 重要 - 適合 Lambda 單執行緒
max_overflow 0 不允許額外連線 重要 - 避免資源浪費
pool_recycle 600 10分鐘後回收連線 重要 - 防止長期閒置連線
pool_timeout 30 獲取連線超時 重要 - 避免無限等待
connect_timeout 10 連線建立超時 重要 - 快速失敗重試
statement_timeout 30000 SQL執行超時(30秒) 重要 - 避免長查詢阻塞

超時設定的重要性

1. pool_timeout=30 - 獲取連線超時

2. connect_timeout=10 - 連線建立超時

3. statement_timeout=30000 - SQL 執行超時

主要改進效果

  1. 自動死連線檢測：pool_pre_ping=True 會在每次使用前自動檢測連線有效性
  2. 自動重連機制：SQLAlchemy 會自動重建失效連線
  3. 重試邏輯：get_session() 內建重試機制，提高穩定性
  4. 適合 Lambda：連線池設定針對 Lambda 環境優化
  5. 更好的錯誤處理：區分連線錯誤和其他錯誤類型

最佳實踐建議

Lambda 連線管理原則

  1. 不要手動關閉連線池：讓 SQLAlchemy 和 Lambda 自動管理
  2. 重用連線池實例：使用全域變數在容器生命週期中重用
  3. 設定適當超時：避免長時間等待或執行
  4. 監控連線狀態：使用 application_name 標識來源

Session 生命週期理解

重要觀念：

  • session.close() = 歸還連線到連線池（連線仍活著）
  • engine.dispose() = 真正關閉所有資料庫連線
  • 連線池中的連線可以被重用，提高效能

常見問題解答

Q1: 為什麼不需要手動關閉連線池？

A: 在 Lambda 環境中，連線池應該在 container 生命週期中保持活躍。手動關閉會導致下次請求需要重新建立連線，增加延遲。

Q2: pool_pre_ping 會不會影響性能？

A: 會有微小的額外開銷，但相比解決連線問題的價值，這個成本是值得的。而且 SELECT 1 是非常輕量的操作。

Q3: 如何確認設定是否生效？

A: 查看 CloudWatch 日誌，應該能看到：

  • SQLAlchemy Engine 建立成功的日誌
  • 減少的連線錯誤
  • 自動重試的日誌記錄

Q4: 可以增加 pool_size 嗎？

A: 不建議。Lambda 是單執行緒環境，pool_size=1 已經足夠。增加只會浪費資源。

重要提醒：

  • pool_pre_ping=True 是解決問題的關鍵設定
  • Session 關閉只是歸還連線到連線池，不會關閉實際連線
  • 在 Lambda 環境中應避免手動關閉連線池
  • 使用命名參數（:parameter）而非位置參數（%s）更安全
  • 記得在 requirements.txt 中加入 sqlalchemy

這個解決方案有效解決了 Lambda 環境中的資料庫連線穩定性問題，提供了自動重連、連線檢測和錯誤重試等關鍵功能。
