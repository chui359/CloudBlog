WSL2 與 Docker Desktop 虛擬磁碟 (docker_data.vhdx) 容量膨脹問題

前言

在 Windows 環境下使用 Docker Desktop 配合 WSL2 處理一段時間後，突然發現 Docker 的虛擬硬碟檔（docker_data.vhdx）膨脹至破百 GB（我高達 147 GB），但透過 docker system df 檢查時，實際容器與映像檔卻僅佔用數 GB 的情況。

本篇文章旨在記錄此問題的根本成因、排查確認方式，並提供不遺失任何現有 Docker 容器、映像檔與資料庫資料的完整無損壓縮瘦身實作步驟，以及後續長遠防範與最佳實踐配置。

簡介

1. 核心問題

  • 空間假性佔用：docker_data.vhdx 在實體磁碟佔用大量容量，但 Docker 內部實際資料僅約 2~3 GB。
  • 根本原因：WSL2 虛擬磁碟採用動態配置（Dynamically Expanding VHDX）。當下載映像檔或建置專案時，檔案會自動擴增；但在 Linux 內部刪除資料後，Windows 主機端的 VHDX 檔案並不會自動釋放空間與縮減大小，導致大量未使用的零區塊滯留。

2. 處理辦法

  1. **內部區塊回收 (TRIM)**：進入 WSL 內部對 Docker 磁區執行 fstrim，標記釋放已刪除的區塊。
  2. **外部實體壓縮 (Compact)**：完全停止 Docker Desktop 與 WSL 後，在 Windows 管理員權限下使用 Optimize-VHD 或 diskpart 進行無損壓縮收縮。
  3. 路徑轉移與日常防護：將虛擬磁碟搬遷至容量充足的磁碟分割區（如 D 槽），並建立定期清理快取的維護機制。

步驟 5：長遠維護與防範措施

  1. 遷移虛擬磁碟至其他硬碟分割區（如 D 槽）：

    • 開啟 Docker Desktop 點選右上角齒輪 「Settings」 -> 「Resources」 -> 「Advanced」。
    • 找到 「Virtual disk location」 設定。
    • 選擇容量較大的磁碟路徑（例如：D:\Docker\wsl），點選 「Apply & restart」，Docker 會自動遷移資料檔。

備註：

  • 執行 Optimize-VHD 或 diskpart 期間切勿強制中斷或啟動 Docker，以免導致虛擬磁碟結構損毀。
